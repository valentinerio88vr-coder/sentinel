Complete setup & user guide

Sentinel

A self-hosted safety app for your own children's phones: live location, arrival alerts, an SOS button, and screen-time controls. Everything runs on your computer — no subscriptions, no third-party servers, no company reading your family's data.

1. Getting started

What this is — and what it isn't

Sentinel has three parts:

The console

A web page you open in your browser. Shows a map, arrival alerts, and a feed of activity. This is what you look at.

The server

A small program that runs on your computer. It stores everything and sends alerts to the console. Nothing leaves your machine unless you configure it to.

The phone app

An Android app installed on your child's phone. It reports location, messages and calls to your server, and carries the SOS button.

Read this before you install anything

The app is visible on your child's phone at all times. A permanent notification sits in their status bar, they can open the app to see exactly what is shared, and they can switch it off with one tap. That is not a limitation to work around — it is the design. Hidden monitoring apps are the ones that get a child to stop trusting you, and in many countries they are illegal even for a parent to install. See Legal & ethics.

What you need

RequirementDetails
Python 3.10+On the computer that runs the server. Windows, macOS or Linux.
An Android phoneAndroid 8.0 (API 26) or newer. This is the phone being monitored.
A home networkThe phone must be able to reach your computer. Same Wi-Fi makes this easy.
Android Studio optional Only if you want to build the phone app yourself. Anyone comfortable with a terminal can do it.
Time estimate

Server running: about 5 minutes. First phone enrolled and reporting: 30–45 minutes, most of it waiting for Android Studio to download the SDK.

2. Install and run

Option A — double-click the launcher (Windows)

In the project folder, double-click run.bat. It does everything for you:

1

Finds Python

Checks for py or python. If neither exists it tells you exactly what to install.

2

Creates a virtual environment

An isolated Python installation in .venv\ so nothing is installed system-wide. First run only; subsequent runs skip this.

3

Installs dependencies

Four packages: FastAPI, Uvicorn, Pydantic and websockets. Needs internet once. A marker file .venv\.deps-ok prevents reinstalling every time.

4

Generates a signing secret

Writes a random key to data\secret.key. This signs login sessions — if it changes, everyone gets logged out. Keep it.

5

Checks the port and starts

If port 8000 is free, it starts the server and opens http://127.0.0.1:8000 in your browser automatically.

You should see something like this in the black window:

  ############################################
  #   SENTINEL - Family Safety Console       #
  ############################################

  [1/5] Python found: 3.12.4
  [2/5] Virtual environment ready
  [3/5] Dependencies already installed
  [4/5] Using existing signing secret
  [5/5] Checking port 8000...

  Starting Sentinel at http://127.0.0.1:8000
  Press Ctrl+C or close this window to stop it.

INFO:     Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)
Keep the window open

Closing the black window stops the server. Alerts only reach you while it is running. You can minimise it — that's what the desktop shortcut does.

Option B — the terminal (macOS / Linux)

cd sentinel
./run.sh          # does the same five steps
# or pick a different port:
SENTINEL_PORT=9000 ./run.sh

Option C — manual, if you'd rather see every step

cd sentinel/backend
python3 -m venv ../.venv
source ../.venv/bin/activate          # Windows: ..\.venv\Scripts\activate

pip install -r requirements.txt

export SENTINEL_SECRET=$(python3 -c "import secrets;print(secrets.token_hex(32))")
uvicorn app.main:app --host 0.0.0.0 --port 8000
0.0.0.0 vs 127.0.0.1

127.0.0.1 accepts connections only from this computer — right for testing the console. 0.0.0.0 lets other devices on your Wi-Fi connect, which you need once a real phone is reporting. Use 0.0.0.0 when you get to enrolment.

Option D — load a demo family

Want to see the console with realistic data before touching a real phone? With the server running:

cd sentinel
.venv/bin/python tools/seed_demo.py        # Windows: .venv\Scripts\python tools\seed_demo.py

Creates two simulated children with home and school geofences, a day of movement, an SOS event and a set of alerts. Sign in with:

parent@sentinel.example.com
SentinelDemo2026
Safe to experiment

This is simulated data generated locally. Nothing here touches a real phone or a real child. Delete the account later by removing backend/data/sentinel.db.

3. Desktop icon & autorun

Windows — one click to install the icon

Double-click install-desktop-icon.bat. It creates Sentinel on your Desktop with a proper icon, pointed at run.bat.

  Creating a Sentinel shortcut on your Desktop...

  Shortcut created: C:\Users\You\Desktop\Sentinel.lnk
  Target:           C:\...\sentinel\run.bat
  Icon:             C:\...\sentinel\assets\sentinel.ico

  Done. Look for "Sentinel" on your Desktop.

The shortcut starts minimised, so the console window stays out of your way while the server runs.

Pin it to the taskbar or Start menu

  1. Find Sentinel on your Desktop.
  2. Right-click → Show more options (Windows 11) → Pin to taskbar.
  3. Or drag it onto the Start button to pin to Start.

Make it start with Windows (optional)

1

Press Win + R, type shell:startup, press Enter.

2

Copy the Sentinel desktop shortcut into the folder that opens.

3

Reboot to confirm. The server starts minimised and the console is one click away.

Only do this if the computer is always on

If the machine sleeps or shuts down, the server stops with it and the phone's reports queue up until it returns. That's not data loss — the phone holds everything and uploads on reconnect — but you won't get live alerts while the server is down.

macOS / Linux

./tools/make-desktop-icon.sh

On macOS this creates ~/Desktop/Sentinel.app with the icon; on Linux it creates ~/Desktop/sentinel.desktop. Both simply open a terminal and run run.sh.

The icon itself

To regenerate it at any size (the .ico contains 16, 24, 32, 48, 64, 128 and 256 px):

python tools/make_icon.py
# writes assets/sentinel.ico and assets/sentinel.png

4. Create your account

Open http://127.0.0.1:8000. You'll see the sign-in screen:

1

Click "Create one"

Fill in a family name (e.g. The Sharma Family), your email, and a password of at least 10 characters.

2

Sign in

You land on the Family page. With no devices yet, it says "No devices yet" — that's expected.

3

Turn on two-factor now

Go to Settings → Set up two-factor. Scan the secret into Google Authenticator, Authy or 1Password, then enter the 6-digit code.

Do not skip step 3

This account shows where your child is at all times. A password alone is a thin lock — and if someone gets in, they see everything. Two-factor takes two minutes to set up.

5. Add a child's phone

This creates an enrolment code that links one phone to your account. It doesn't start monitoring — the phone has to accept the consent notice first.

1

Click + Add a device

A panel opens at the top of the Family page.

2

Fill in the four fields

Device name (Aarav's phone), the child's name, their email, and the relationship — keep it on My child (parental).

3

Press Get code

You get an 8-character code like 1CBCF32F, valid for 60 minutes.

One code, one phone

Codes are single-use and expire after an hour. If one leaks or expires, just make another — there's no limit. A used code can never be replayed.

6. Build the Android app

Honest warning before you start

The Android project in sentinel/android/ has not been compiled in the environment where it was written — there was no Android SDK available. The code is complete and written against API 34, but expect to fix a handful of small build errors on your first attempt. Budget a couple of hours, not ten minutes. Everything below is the standard path.

Install the tools

1

Install Android Studio

Download from developer.android.com/studio. It bundles the SDK, the build tools and a JDK.

2

Run the setup wizard

Accept the defaults. When it finishes, go to More Actions → SDK Manager → SDK Platforms and tick Android 14.0 (API 34). Then open the SDK Tools tab and confirm Android SDK Build-Tools is installed.

3

Open the project

File → Open, choose the sentinel/android folder (not the parent folder). Let Gradle sync finish — the first one downloads dependencies.

Build the APK

In Android Studio: Build → Build Bundle(s) / APK(s) → Build APK(s). The APK lands in android/app/build/outputs/apk/debug/app-debug.apk.

Or from a terminal:

cd sentinel/android
./gradlew assembleDebug

# Windows:
gradlew.bat assembleDebug

Install it on the phone

1

Enable developer options

On the phone: Settings → About phone → tap Build number seven times.

2

Enable USB debugging

Settings → System → Developer options → USB debugging → On.

3

Connect and install

adb devices                        # the phone should appear; accept the prompt on it
adb install app/build/outputs/apk/debug/app-debug.apk
No cable?

Copy the APK to the phone by any means (USB storage, a file-transfer app, Google Drive), then open it on the phone and allow "Install unknown apps" for your file manager when prompted.

What the app does and doesn't collect

CollectedNever collected
  • SMS messages one-time codes filtered out on the phone
  • Call log — number, time, duration
  • Last known location at each sync
  • List of installed apps
  • SOS button presses
  • WhatsApp, Telegram, Signal or any app's messages
  • Photos, files, keystrokes, screenshots
  • Microphone, camera, screen recording
  • Passwords or banking credentials
  • One-time passcodes

7. Enrol on the phone

Do this sitting next to your child

Not at the kitchen table with the phone, not while they're at school. Read the consent screen with them. The first five minutes decide whether this app stays on the phone.

Find your computer's address

The phone needs to reach your server over the network. On the computer:

# Windows
ipconfig
# look for IPv4 Address, e.g. 192.168.1.42

# macOS / Linux
ifconfig | grep "inet "
# or: ip addr show

Your server address is then http://192.168.1.42:8000 — not 127.0.0.1, because on the phone that means "the phone itself".

Start the server with the right host

If you used run.bat, it binds to 127.0.0.1 and the phone cannot connect. To allow other devices, run with 0.0.0.0:

cd sentinel/backend
..\.venv\Scripts\python -m uvicorn app.main:app --host 0.0.0.0 --port 8000

Walkthrough

1

Open Sentinel Agent on the phone

If Android warns about an unknown app, that's expected for a self-built APK.

2

Enter the server address

http://192.168.1.42:8000 — with http:// and no trailing slash.

3

Enter the 8-character code

The one from step 5. Not case-sensitive.

4

Read the consent notice together

It lists exactly what is shared and what is not. Scroll to the bottom.

5

Your child ticks the box

Let them do it. It's their phone and their decision.

6

Grant permissions, then tap the button again

Android asks for SMS, call log, location and notifications. All are needed — with any refused, that type of data simply won't be reported.

7

Allow location "all the time" (optional)

Android will ask. Without it, location is only reported while the app is open. With it, reports arrive in the background. It's a fair thing to discuss, not to click through.

Confirm it worked

  • The phone shows a permanent notification: "Sentinel is sharing with your parent".
  • Within a minute or two, the console shows the device as active.
  • Open the device page — a location appears once the first sync completes.
If nothing appears

Syncs run on a 15-minute schedule, so the first report can take a little while. To force one: open the app on the phone, or on the console use Locate now and wait for the next sync. See Troubleshooting if it stays empty.

8. Set up places (geofences)

A geofence is a circle on the map. When your child enters or leaves it, you get an alert. Two places cover most of the value: home and school.

1

Open the child's page

From the Family page, click their card.

2

Click + Add place

Under "Places watched" on the right.

3

Name it and pick a type

School is worth using over other — arrival and departure alerts for a school zone are marked higher priority.

4

Set the radius

The form pre-fills with your child's last known position, which is usually not the school gate. Adjust the coordinates, or set a generous radius. Guidance below.

Choosing a radius

RadiusGood forTrade-off
150 mHome, if you're in a detached house Flappy in dense apartment blocks — GPS drift crosses the line repeatedly
200–300 m recommended School, a friend's building, home in a city Occasional alert a minute or two early or late
500 m+A whole campus or neighbourhood Misses the difference between "at school" and "two streets away"
The app already handles GPS noise

A location fix whose accuracy circle is wider than the zone radius is ignored entirely. Entering a 250 m school zone on a 900 m cell-tower fix produces no alert, because it would be a guess. The first fix after adding a zone sets a baseline without firing anything, and repeat alerts are suppressed to one per zone per direction per hour.

9. Set up SOS

This is the feature that earns the app its place on the phone. Your child can trigger it from the lock screen in two taps, without unlocking.

1

On the phone, pull down the notification shade twice

To reveal the full quick-settings grid.

2

Tap the pencil / edit icon

The tile editor. You may need to swipe to a second page of tiles and drag from "Hold and drag to add tiles".

3

Drag the SOS tile into the grid

Put it somewhere easy to hit — top-left is often easiest with a thumb.

4

Test it

Tell your child you're testing, tap SOS, and watch the console. You should get a red EMERGENCY ALERT banner and a toast notification within a few seconds.

Why quick settings and not a power-button shortcut

Quick-settings tiles are reachable from the lock screen on every Android version without granting extra permissions. Power-button shortcuts vary by manufacturer and often require accessibility permissions, which are broad and hard to justify.

There is also an SOS — alert my parent now button inside the app, on the status screen, for when the phone is already unlocked.

What happens when SOS fires

  1. The event is written to the phone's local outbox immediately — it works with no signal.
  2. On the next successful sync it uploads and becomes a critical alert.
  3. The console shows a red banner at the top of every page and a toast, pushed over a live socket.
  4. It stays until you acknowledge it.

10. Screen time & app blocking

On the child's page, under Screen time & apps, set an allowed window (e.g. 06:30 to 21:30) and list any apps to block by package name (e.g. com.tiktok, com.zhiliaoapp.musically).

This one is stored and delivered, not enforced

The server saves the policy and hands it to the phone on the next sync, and the phone stores it — but the Android agent does not yet apply it. Enforcing a screen-time window means using DevicePolicyManager (which needs device-owner provisioning) or an accessibility service. That work is not done. Don't promise your child it will lock their apps, because it won't.

To find an app's package name: Play Store → the app → Share, and read the ?id= parameter in the link.

11. Reading alerts

RuleSeverityWhat it means
soscritical Your child pressed the SOS button. Treat it as real until proven otherwise.
zone_enterinfo / high Arrived at a watched place. High when the place is typed school.
zone_exitinfo / high Left a watched place. Includes distance from the centre.
device_offlinemedium No sync for over an hour. Usually flat battery or no signal — check before worrying.
app_installedinfo A new app appeared on the phone.
unusually_long_callinfo A call over an hour. Almost always benign.

The device page

Remote commands

  • Locate now — asks the phone for a fresh fix. Note it returns the phone's last known position, so if the phone has been still, the answer is the same.
  • Ring device — plays the alarm at full volume for 15 seconds. Useful for a lost phone, and very obvious to whoever is holding it. That's deliberate.
  • Sync now — nudges an immediate upload.
Commands are not instant

They queue on the server and the phone picks them up on its next sync — up to 15 minutes. The phone shows a notification when one runs. There is no silent command channel.

12. The conversation to have first

This is the part most guides skip, and it matters more than any setting.

A script that works better than "because I said so"

"I've put an app on your phone. It shares your location with me, and it has an SOS button you can press from the lock screen if you ever need me fast. It also shows me your messages and calls — I'm telling you that because you can see it all yourself in the app, and you can switch it off whenever you want. I'd rather you knew than didn't."

Things that make it go badly

  • Installing it secretly. They will find the notification. Then the app is a lie, not a safety net, and it comes off.
  • Using location as an accusation. "You were at Rohan's house, not at tuition." Do that twice and they'll leave the phone at home — you've made them less safe, not more.
  • Reading message content as your first move. Location and SOS are the safety features. Reading a 15-year-old's messages is a different act with a different cost. Decide deliberately, ideally before you install it.
  • Pretending it can't be turned off. It can. Saying otherwise is the fastest way to be caught in a lie.

Things that make it go well

  • Install it together, and let them tick the consent box.
  • Tell them what triggers an alert before it happens, so an alert is never an ambush.
  • Agree a sunset: "we'll review this in three months."
  • If they switch it off, treat that as information, not a technical failure to route around.

13. How it works

Data flow

┌────────────────┐   enrol + consent    ┌──────────────────────────────────────┐
│ Sentinel Agent │ ────────────────────► │  FastAPI server (your computer)      │
│ (Android)      │ ◄──── device token ── │                                      │
│                │                       │  POST /api/sync ──► events (deduped) │
│ • SMS          │   POST /api/sync      │        │                             │
│ • Call log     │ ────────────────────► │        ├──► job queue                │
│ • Location     │   ◄── commands ────── │        │      ├─ alert rules         │
│ • App list     │   ──► acks ─────────► │        │      ├─ geofence checks    │
│ • SOS tile     │                       │        │      └─ offline sweeps     │
│                │                       │        ▼                             │
└────────────────┘                       │   WebSocket /ws ──► console          │
        │                                │   audit log (every read)             │
        │ permanent notification         └──────────────────────────────────────┘
        └► child can stop at any time

Design decisions worth knowing

The upload path stays fast

The phone's upload endpoint only writes rows and queues a job. Alert rules, geofence maths and offline sweeps run in a separate worker thread. A slow rule can never stall a child's upload.

The job queue is real

Jobs are claimed atomically — two workers can't take the same one. Failures retry with exponential backoff up to five attempts, then sit visibly in a failed state instead of vanishing. A worker that dies mid-job has its lease reclaimed after two minutes.

Duplicates are impossible

Every event carries a fingerprint (SHA-256 of its contents). Send the same batch five times and the timeline still shows one copy. This matters because phones retry aggressively on bad connections.

The phone holds its own queue

No signal for a day? The app stores up to 5,000 events on the device and uploads them when the connection returns. Nothing is lost by being offline.

Everything is auditable

Every time location data is read — by a map view or an export — it's written to an audit log with the account, IP and timestamp. You can show your child exactly who looked and when.

Data storage

One SQLite file: backend/data/sentinel.db. Back it up by copying that file. Delete it to wipe everything. No cloud, no replication, no third party.

16. Command line & testing

Run the test suite

73 checks covering auth, 2FA, enrolment, consent enforcement, ingest and dedupe, the job queue, geofencing with hysteresis, the command channel, policy delivery, audit logging and deletion. Needs the server running.

cd sentinel
.venv/bin/python tools/e2e_test.py
# Windows: .venv\Scripts\python tools\e2e_test.py

# against a different host:
.venv/bin/python tools/e2e_test.py http://192.168.1.42:8000

Expected output ends with:

73 passed, 0 failed

Simulate a phone

Useful for developing without a device. Claims a code exactly the way the Android app does, then posts realistic traffic through the real ingest API.

.venv/bin/python tools/simulate.py --code ABCD1234 --days 3 \
    --base http://127.0.0.1:8000

Inspect with curl

# health, queue depth and live subscriber count
curl http://127.0.0.1:8000/api/health

# sign in and keep the token
TOKEN=$(curl -s -X POST http://127.0.0.1:8000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"you@example.com","password":"your-password"}' | python3 -c "import json,sys;print(json.load(sys.stdin)['token'])")

# list devices
curl -s http://127.0.0.1:8000/api/devices -H "Authorization: Bearer $TOKEN"

Reset everything

This deletes all data permanently

Stop the server first, then delete the database file. There is no undo.

# stop the server (Ctrl+C), then:
rm backend/data/sentinel.db*        # Windows: del backend\data\sentinel.db*
# start again — it rebuilds an empty database and you create a new account

Back up

# with the server stopped, copy the whole data folder
cp -r backend/data backups/$(date +%Y-%m-%d)
# Windows: xcopy backend\data backups\%DATE%\ /E /I

17. Troubleshooting

SymptomCause and fix
"Python was not found" Python isn't installed or isn't on PATH. Install from python.org and tick "Add python.exe to PATH" during setup, then re-run run.bat.
Port 8000 already in use Something else is using it, or Sentinel is already running. Check http://127.0.0.1:8000 in a browser. To use another port: SENTINEL_PORT=9000 ./run.sh, or edit PORT= in run.bat.
PowerShell won't run the shortcut script Execution policy. The .bat passes -ExecutionPolicy Bypass itself, so run install-desktop-icon.bat, not the .ps1 directly. Or run: powershell -ExecutionPolicy Bypass -File tools\make-shortcut.ps1 -Root .
Desktop icon is blank / generic Windows icon cache. Press Win+R, run ie4uinit.exe -show. If that fails, delete %LocalAppData%\IconCache.db and restart Explorer.
Bottom-left says "reconnecting…" The live socket is down — alerts won't pop up. Usually a missing websockets package: run .venv\Scripts\pip install websockets and restart. Check the server console for No supported WebSocket library detected.
Console logs you out immediately The signing secret changed (server restarted without data/secret.key), or a request failed with 401. Sign in again. If it repeats, delete data/secret.key, restart, and sign in once more to get a fresh key.
Phone can't reach the server Three usual causes: (1) server bound to 127.0.0.1 — restart with --host 0.0.0.0; (2) wrong IP — re-check with ipconfig, and use the phone's Wi-Fi network, not mobile data; (3) firewall blocking Python — allow it on private networks when Windows prompts.
Device shows pending forever The code was never claimed. Codes expire after 60 minutes — generate a new one and re-enter it on the phone. Check the phone's server address has no trailing slash.
No location on the map Location permission not granted, or the phone has no fix yet. Android Settings → Apps → Sentinel → Permissions → Location → allow. Indoors, GPS can take a minute. On the console, press Locate now and wait for the next sync.
Nothing syncs after a restart Check the device is still active, not paused or revoked. Battery optimisation can also kill background work: on the phone, set Sentinel to Unrestricted under Settings → Apps → Sentinel → Battery.
Gradle build fails on first open Usually a missing SDK platform. SDK Manager → SDK Platforms → Android 14 (API 34). Then File → Invalidate Caches → Restart. If Kotlin version errors appear, let Android Studio update the Gradle plugin when it offers.
"Database is locked" Two server instances are running against one database. Close both, then start exactly one. Check for a stray uvicorn process in Task Manager.
Too many alerts Zone radius is too small for GPS accuracy — raise a noisy home fence from 150 m to 250 m. City apartment blocks genuinely need wider circles.

18. Security checklist

Do these before you rely on this for anything real.

  • Two-factor enabled on your parent account (Settings)
  • Password at least 12 characters and not reused anywhere else
  • data/secret.key backed up somewhere safe, and never committed or shared
  • Server not exposed to the internet — home Wi-Fi only, no port forwarding
  • If you do expose it: put it behind HTTPS (Caddy or nginx) and change nothing else until you have
  • Computer requires a login and doesn't auto-login
  • backend/data/sentinel.db backed up, and the backup is also protected
  • Old devices deleted from the console once a phone is retired
  • You've read Legal & ethics for your jurisdiction
The one thing that actually matters

Device tokens and session tokens travel in HTTP headers. Over plain HTTP on an open Wi-Fi network, anyone on that network can read them and impersonate your phone or your account. At home on a network you control, acceptable. In a café, not. Put it behind HTTPS before you treat it as production.

19. Known limits

Stated plainly, so you don't discover them at a bad moment.

LimitWhat it means in practice
Android app is uncompiled Written against API 34 but never built in the environment that produced it. Expect to fix build errors on first attempt.
No push notifications Alerts reach an open console tab. Close the browser and you won't be told. This is the biggest gap for a safety tool; FCM plus web push is the fix.
15-minute sync floor Android's WorkManager minimum. Location is not continuous — it's a snapshot at each sync, plus whatever a Locate now command returns.
Policy not enforced Screen-time and blocked apps are stored and delivered, but the phone doesn't apply them yet.
Map is drawn, not tiled No streets or place names — just your points, zones and trail, auto-fitted. Adding Leaflet or Google Maps is a contained change to renderMap().
SQLite, single computer Fine for a family (2–10 devices). Not a fleet. Server must stay on for live data.
No remote data wipe You can revoke a device, but you can't command the phone to erase its local queue.
Android-only No iOS agent. iOS wouldn't permit background SMS or call-log access anyway.

20. Legal & ethics

Not legal advice

This is orientation, not counsel. Laws differ by country and state, and they change. If you're unsure, ask a lawyer before installing anything.

What's generally defensible

Monitoring your own minor child, on a phone you own and pay for, with the app visible and disclosed to the child. That is the case this software is designed for, and every default reflects it.

What is not

  • Installing it on another adult's phone — a partner's, an ex's, an employee's personal device. In many jurisdictions this is a criminal offence, not a civil matter.
  • Hiding the app from the person carrying the phone.
  • Continuing after your child turns 18. At that point only their consent is a lawful basis.
  • Collecting message content or credentials without disclosure. The app deliberately filters one-time passcodes on the device and never transmits them.

India

  • IT Act 2000, §66 — unauthorised access is criminal; this covers installing monitoring software on someone else's device.
  • DPDP Act 2023 — lawful basis, purpose limitation, data minimisation, erasure on request. The console's Export data and device-delete endpoints support these duties.
  • Puttaswamy (2017) — informational privacy is a fundamental right; courts expect necessity and proportionality, including within a family.

European Union / UK

  • GDPR — a DPIA is effectively mandatory before systematic monitoring, even in a household context where the household exemption may not cover a tool of this kind.
  • Several member states criminalise covert tracking outright, regardless of family relationship.

United States

  • ECPA / Wiretap Act and Stored Communications Act — intercepting electronic communications without consent is a federal crime.
  • CFAA — unauthorised access to a computer; a phone counts.
  • State law varies sharply; several states criminalise installing tracking software on another adult's phone with no exception at all.
